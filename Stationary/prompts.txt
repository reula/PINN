EDITORIAL NOTE (added after the fact; the prompt above is left verbatim)

The second-order Robin condition quoted in the prompt above,

    (lambda - 1)/r + 3 d_r lambda + d_r^2 lambda = 0 ,

is NOT what this repo implements, and it is not a correct higher-order decay condition.
It is not scale covariant and it annihilates no power law at all -- it leaves a residual
even on lambda - 1 ~ rho^-1, which the first-order condition already kills.  The
implemented condition is

    prod_{i<n} (rho d_rho + base + i) (field - field_inf) = 0 ,

which for lambda (base 1) reads  (lambda-1)/rho + d_rho lambda = 0  at n = 1 and
rho^2 lam'' + 4 rho lam' + 2 (lam - 1) = 0  at n = 2.  The trap is multiplying the Euler
factors in d_rho instead of in theta = rho d_rho: they do not commute,
(d_rho + a/rho)(d_rho + b/rho) = rho^-2 (theta + a - 1)(theta + b).

See Laplace_Robin.md section 2, and tests/test_pipeline.py::
test_robin_operator_expansions_match_the_documented_forms, which pins the n = 1..4
expansions to the implementation.
